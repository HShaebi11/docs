The sliders input bundle provides three continuous analog values — `x`, `y`, and `rotation` — each normalized to the range 0–1. A single call to `loop.getSlidersInput()` returns all three as a `SliderBundle`. Loop automatically polls the best available input source on every animation frame: a connected gamepad takes priority, followed by MIDI CC messages, and finally on-screen `<input type="range">` elements that serve as a built-in fallback when no hardware is present.

## The `SliderBundle` type

`loop.getSlidersInput()` returns a `SliderBundle` — a plain object containing three independent `Handle<number>` instances.

```typescript
interface SliderBundle {
  x:        Handle<number>;  // 0–1
  y:        Handle<number>;  // 0–1
  rotation: Handle<number>;  // 0–1
}
```

Each handle can be read, subscribed to, or bound to a DOM element independently. They share a single underlying sampler so the gamepad-vs-MIDI priority logic runs once per frame.

## Getting the bundle

```typescript
import loop from "@theinterfaces-lab/loop";

// Returns { x, y, rotation } — each a Handle<number> from 0 to 1
const { x, y, rotation } = loop.getSlidersInput();
```

<Warning>
  Do **not** call `loop.input("sliders")` — it throws an error. The sliders input returns three handles, not one, so it is exposed through the dedicated `loop.getSlidersInput()` function.
</Warning>

## Reading values in a tick loop

```typescript three.ts
import loop from "@theinterfaces-lab/loop";

const { x, y, rotation } = loop.getSlidersInput();

loop.tick(() => {
  mesh.position.x = (x.value - 0.5) * 10;
  mesh.position.y = (y.value - 0.5) * 10;
  mesh.rotation.z = rotation.value * Math.PI * 2;
});

// Or bind to on-screen range inputs
x.bind(xSlider, (v) => { xSlider.value = String(v); });
```

## Input source mappings

The sliders bundle reads from the following physical sources, in priority order:

### Gamepad (highest priority)

When a gamepad is connected and any axis or trigger exceeds the deadzone threshold (0.05), the gamepad becomes the active device and keyboard/on-screen sources are bypassed.

| Slider | Gamepad source | Notes |
|--------|---------------|-------|
| `x` | Left stick axis 0 | Normalized: `(raw + 1) / 2` → 0–1 |
| `y` | Left stick axis 1 | Normalized: `(-raw + 1) / 2` → 0–1 (inverted) |
| `rotation` | Right trigger (button 7) | Raw button value → 0–1 |

### MIDI CC

When MIDI CC messages are received, the active device switches to `"midi"`. See the [MIDI page](/inputs/midi) for full details.

### On-screen fallback

When neither gamepad nor MIDI is active, the bundle uses its own internal handle values as the source. These values are driven by any `<input type="range">` elements you bind to the handles — making on-screen sliders the zero-hardware fallback.

## Detecting and overriding the active device

Use `loop.getSlidersActiveDevice()` to read the current source. Call `loop.setSlidersActiveDevice(device)` to override it programmatically — for example, to force on-screen controls in a testing environment.

```typescript device.ts
import loop from "@theinterfaces-lab/loop";

// Read the current source
const device = loop.getSlidersActiveDevice();
// → "gamepad" | "midi" | "on-screen"

// Override the active device
loop.setSlidersActiveDevice("on-screen");
```

## On-screen fallback sliders

When no gamepad or MIDI device is detected, bind each handle to an `<input type="range">` element. The handle reads back from the element's value on each tick, so the on-screen slider immediately becomes the effective source.

```html index.html
<input type="range" id="x-slider" min="0" max="100" value="50">
<input type="range" id="y-slider" min="0" max="100" value="50">
<input type="range" id="rot-slider" min="0" max="100" value="0">
```

```typescript fallback.ts
import loop from "@theinterfaces-lab/loop";

const { x, y, rotation } = loop.getSlidersInput();

const xSlider   = document.getElementById("x-slider")   as HTMLInputElement;
const ySlider   = document.getElementById("y-slider")   as HTMLInputElement;
const rotSlider = document.getElementById("rot-slider") as HTMLInputElement;

x.bind(xSlider,   (v) => { xSlider.value   = String(Math.round(v * 100)); });
y.bind(ySlider,   (v) => { ySlider.value   = String(Math.round(v * 100)); });
rotation.bind(rotSlider, (v) => { rotSlider.value = String(Math.round(v * 100)); });
```

## Using sliders in a pipeline

Each slider handle emits `value` packets. Wire individual handles into source stages as needed.

```typescript pipeline.ts
import loop from "@theinterfaces-lab/loop";

const { rotation } = loop.getSlidersInput();

const rotSource = loop.source({
  emits: "value",
  read() {
    return { kind: "value", value: rotation.value };
  },
});
```

<Note>
  MIDI is initialized automatically when you call `loop.getSlidersInput()`. There is no separate setup step. See the [MIDI input page](/inputs/midi) for details on CC mapping and browser requirements.
</Note>
